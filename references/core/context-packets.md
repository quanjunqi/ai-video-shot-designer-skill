# 节点上下文包合同

上下文包是导演流程的内部数据复用层。它解决“下游每次重新读取整份项目、重复分析同一内容”的问题，不改变用户可见的阶段和审核顺序。

## 1. 四类数据

- **锁定事实**：剧本、场景空间、镜头和状态等用户已确认对象，按 artifact 版本和 SHA-256 引用。
- **用户决策**：选中的演员、造型、场景母版、调度、镜头、Prompt 和视频审核结果，只从当前已批准版本读取。
- **派生分析**：角色状态映射、连续性索引、覆盖索引和节点上下文，属于可重算结果，不反向修改事实。
- **执行输出**：Prompt、图片、视频和尾帧，必须保留输出文件哈希，并按原有 artifact 合同等待用户确认。

上下文包只携带当前节点所需的最小输入，不把完整台账或历史版本塞入模型请求。所有节点统一通过 `prepare_context(...)` 编译；命令行场景使用 `project_ledger.py context build/inspect`。`config/workflow/context-packets.json` 是节点输入映射的配置源。

## 2. 节点复用边界

```text
选角       = 角色客观需求 + 视觉风格 + 制作规格
造型状态   = 角色状态事实 + 场次/单元覆盖 + 视觉风格/规格
服装/发型/配饰组件 = 单一组件需求 + 已批准组件上游 + 视觉风格/规格，不读取演员
妆容组件   = 演员基准 + 单一妆容需求 + 视觉风格/规格
角色融合   = 演员基准 + 状态方案 + 已确认组件
场景母版   = 场景功能稿 + 视觉风格 + 制作规格
空间调度   = 场景母版/视图组 + 场景功能稿 + 单元覆盖
镜头方案   = 锁定剧本 + 场景空间 + 走位/机位 + 场景母版
Prompt     = 镜头/剪辑方案 + 执行单元资产 + 视觉风格/规格
视频       = 已确认 Prompt + 单元资产 + 角色四视图 + 场景母版 + 上一单元真实尾帧
```

这张表是数据依赖，不是用户审批清单。用户只确认真正会影响后续输出的结果；内部派生包不弹窗要求确认。

## 3. 哈希与失效

上下文的规范化 JSON 使用排序后的键和无时间戳序列化。输入 artifact 的内容、版本、文件哈希或批准状态变化时，输入哈希必须变化。上游替换或拒绝由现有依赖图传播为 `STALE`，并删除引用受影响输入的 `derived_cache` 条目。

典型影响范围：

```text
演员基准 -> 该角色造型、融合、四视图、镜头参考、Prompt、视频
造型组件/定妆 -> 该状态四视图、镜头参考、Prompt、视频
场景母版 -> 场景视图、空间、调度、机位、镜头、Prompt、视频
空间/机位 -> 调度、镜头、Prompt、视频
镜头/剪辑 -> Prompt、视频
视觉风格/制作规格 -> 对应全局下游，剧本事实不失效
```

历史 artifact、审核日志和已接受视频不会因缓存失效被删除。缓存只是“可重算结果的索引”，不是事实删除机制。

## 4. 安全边界

- 只接受 `USER_APPROVED` artifact 进入可执行上下文。
- 每个文件路径必须位于当前项目根目录内。
- 读取 JSON 时严格解析，文件哈希不匹配时停止，不静默使用旧内容。
- 缓存命中不跳过用户审核，不把候选图变成选定图，不将计划尾态冒充真实尾帧。
- 未确认上游时，节点应报告缺失/未批准依赖，而不是自行补全或使用聊天记忆。

视频是动态上下文，必须由调用方显式传入本单元真实使用的全部 artifact keys，至少包括已确认 Prompt、执行单元资产、所有实际角色/造型状态四视图、场景母版，以及上一已接受单元的视频 `actual_tailframe`（第一单元没有上一单元尾帧时不得伪造）。配置中的 `video` 模板仅用于说明依赖形状，不能代替显式列表。编译后的 reference 会记录上下文哈希、相对路径和 artifact keys；视频适配器会重新读取并校验这些内容后再写入请求元数据。
